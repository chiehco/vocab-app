# Audit validation boundaries

`scripts/apply_unit_audit.py` checks the dataset identity, exact old values, editable-field allowlist and an explicit `before` value for every `after` field before writing any public file. Shape validation also runs before the already-applied shortcut. All patches are validated in memory before the receipt and data writes. Negative temporary-fixture tests cover missing old values, incorrect old values, unlisted sentence fields, unknown row identities and a later invalid patch preventing an earlier valid write.

`src/db/unitAudit.testSupport.ts` verifies each recorded current field and reverses only the explicitly recorded corrections for the historical payload comparison. The historical fixture hashes are unchanged. Its negative tests demonstrate that unlisted column changes, row additions and row deletions remain visible to the outer historical hash; unexpected audited values and duplicate audited identities are rejected directly.

The helper alone does not establish that a dataset is complete: it intentionally skips absent full-dictionary rows so the existing starter-subset assertions retain their original meaning. Dataset counts, identities and the unchanged outer historical payload hashes provide completeness checks. `meta.generatedAt` is normalized to the historical value for that comparison; it is not independently validated as an audit timestamp. Current `wordsHash` and `contentHash` are independently recomputed from all saved full-dictionary files before historical metadata normalization. The helper does not prove source semantics, image correctness or UI persistence; those require the per-card review and reopen evidence.

An already-applied row is accepted only after manifest shape validation and matching every requested new value. This is an idempotency check, not proof that a supplied old value describes an earlier release; retained receipts and the outer fixed historical hashes cover that history.
